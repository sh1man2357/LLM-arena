# 架构与实现验收：v0.1 核心与 v0.2 扩展

## 模块边界

| 模块 | 职责 | 输入与输出 |
| --- | --- | --- |
| Rules Engine | 纯整数确定性结算 | 世界状态 + 全体动作/故障 → 下一状态 + 事件 |
| Map Generator | Seed 生成合法地图 | Seed + 生成器版本 → 地图 + 元数据 |
| SDK / Compiler | C++ 解码与 ABI 包装、统一编译 | 源码 + 工具链 → WASM + 日志 |
| Bot Runtime | 独立沙箱、fuel、调用与故障分类 | WASM + 观察 → 动作/故障 |
| Match Runner | 初始化与逐 Tick 驱动 | 冻结配置 + Bot → Replay + 单局结果 |
| Tournament Runner | 全配对和出生位交换 | 案例清单 + entrant 清单 → 完整结果集 |
| Reporter | 汇总、区间与辅助统计 | 完整结果集 → JSON 与可读报告 |
| Replay Viewer | 回放已记录状态和事件 | 文本 / 图形回放与真实增量直播已有实现；完整异常恢复及体验验收待完成 |

引擎不依赖 WASM 或 UI；测试可直接注入动作。运行时不修改世界；Match Runner 收齐动作后只推进一次引擎。回放器不能决定比赛规则。

实现采用 Python 3.12 宿主、Wasmtime 49.0.0 和 WASI SDK 33.0，见 [实现决策](./07-decisions.md)。规则、地图、报告和回放使用 Python 标准库；Bot 的统一开发条件由冻结 SDK 和编译参数定义。

## 最小入口契约

v0.1 CLI 已具备以下能力，实际命令见根目录 README：

- 编译提交：读源码，输出 WASM、哈希和诊断。
- 资格验证：输出通过/失败和精确原因。
- 单局运行：指定配置、地图 Seed、Bot Seed 和出生映射，输出 Replay 与结果。
- 批量运行：读取冻结清单，生成预定调度并运行，可恢复已完成任务。
- 报告生成：拒绝静默汇总不完整调度。
- Replay 校验：从初始状态和已记录动作重建世界，比较状态哈希与结果。
- Replay 查看：按 Tick 输出地图、实体、动作与事件。

## Replay v0.1 数据契约

已实现格式为 UTF-8 JSON Lines，首行是 header，后续为 tick，末行为 result；整数种子超过 JSON 安全整数范围时以十六进制字符串存储。所有 64 位 Bot Seed 必须用固定 16 位小写十六进制字符串。

header 至少包含：schema_version、match_id、benchmark_id、组件版本/哈希、规则参数、初始地图和哈希、map_seed、bot_seed、entrant 到槽位映射、初始化结果、完整初始世界状态。

每个 tick 记录：

- tick 编号与结算前状态哈希。
- 所有被调用 Bot 的原始返回值或故障类型，以及 fuel 用量。
- 转换后的动作、连续/累计故障计数和本 Tick 淘汰者。
- 移动、放置、爆炸、软墙销毁和死亡事件；死亡保留归因 owner 集合。
- 结算后完整世界状态与状态哈希。

result 包含结束原因 `last_survivor / all_eliminated / tick_limit / initialization_end / infrastructure_failure`、结算次数、存活者、死亡 Tick、并列组、每 Bot 名次分和辅助统计。基础设施失败不产生有效名次分。

未执行 Tick 的初始化结束局，header 后直接写 result，结算次数为 0。死亡时间 `-1` 必须使用有符号字段；仍存活者 death_tick 为 null，不使用看似合法的 Tick 代替。

文件必须保留 Seed，但对外展示时可生成去除保密种子的副本，并标明该副本无法用于完整 Bot 重跑。初始地图和动作足以做世界回放，不等于足以重新执行 Bot。

## 确定性与校验

游戏状态的规范哈希输入定义为：固定字段顺序的紧凑 UTF-8 JSON、无 BOM、无空白；顺序为 `tick, grid, players, bombs, next_bomb_id, fault_counters`。tick 表示下一次要结算的编号；每次结算后加 1，包括结束 Tick。

grid 是行优先地形整数数组。players 按 id 排序，字段顺序为 `id, x, y, alive, death_tick`；bombs 按 id 排序，字段顺序为 `id, owner_id, x, y, explode_at_tick, range`；fault_counters 按玩家 id 排序，字段顺序为 `id, consecutive, total`。宽高和规则参数在 header 中固定。哈希采用 SHA-256，小写十六进制。实现时给出固定输入与期望哈希测试向量。

不把宿主执行时间和 fuel 用量放入世界状态哈希；这些仍保留为运行证据。Bot 私有内存不属于世界状态，动作一致不能证明私有内存一致。

两类复现分别验收：

1. **世界回放：** 根据初始状态和记录的动作/故障逐 Tick 重算，所有状态哈希与结果相同。
2. **Bot 重跑：** 使用相同 WASM、Seed、运行时和预算再次调用 Bot，动作/故障序列和世界哈希相同。

若发生差异，保留首个不同 Tick 的观察、输出与版本清单，诊断后重新验收，不能只用录像流畅作为复现证据。

## 实现顺序

### 阶段 1：规则核心

实现固定地图和注入动作的单局引擎，先验收同时移动、爆炸闭包、墙体快照、死亡并列和 Tick 上限。没有真实 Bot 也能完整检查规则。

### 阶段 2：地图与回放

实现固定 RNG、对称地图、合法性检查、状态哈希、JSONL Replay 和文本回放。对已冻结测试 Seed 保存期望地图和状态轨迹。

### 阶段 3：SDK 与沙箱可行性

选择并固定支持可恢复 fuel trap 的运行时；做最小 C++ WASM 程序验证工具链、禁用导入、内存上限、ABI 和初始化。确认 watchdog 与正式 fuel 故障可区分。

用正常 Bot、无限循环、越界访问、内存增长失败、非法返回值、状态累计 Bot 检查边界；确认超 fuel 后内存保留以及下一次调用恢复。若运行时不满足契约，先更新设计再继续，不能凭空假设支持。

### 阶段 4：Baseline 与批量闭环

Random 使用固定 RNG；Safe 优先避免可计算的爆炸危险；Heuristic 增加安全放弹和寻路。它们共享 SDK、资源限制和正式比赛规则。冻结版本后运行 50 地图、每对 100 局，核对完整调度与统计。

### 阶段 5：首次模型评测

使用 60 分钟交卷任务书，冻结任务包，收集提交，再打开隐藏比赛集。输出原始结果、资格失败、Replay 和统计报告。图形观赛及管理能力纳入下述 v0.2 方案；长期 Rating、多人数调度继续后置。

## 必要验收检查

| 范围 | 验收重点 |
| --- | --- |
| 移动 | 同格争抢、交换、依赖链、环、墙、炸弹、故障释放位置 |
| 爆炸 | T+4 到期、连锁新炸弹、软墙快照、炸弹阻挡、死者炸弹 |
| 终局 | 同 Tick 并列、全灭、初始化全败、时间上限 |
| 协议 | 小端布局、精确长度、数组顺序、种子高低位和缓冲边界 |
| 资源 | fuel、trap 后恢复、64 MiB 上限、禁止导入与 start section |
| 地图 | 对称、出口、连通、固定 RNG、重复地图检测 |
| Replay | 初始状态完整、逐 Tick 哈希、Bot 重跑与世界回放 |
| 评测 | 换边映射、Bot Seed 跟随 entrant、完整调度、失败不静默删除 |

只做与这些行为相关的必要检查，不以大量重复执行同一确定性比赛替代地图覆盖。运行时、SDK 或规则发生变化后，重验受影响范围并更新 benchmark_id。

## v0.2 扩展边界

新增 `web/` 客户端与 `service/` 本地 API / 作业 / 索引层，详见 [服务架构](./10-v0.2-service.md)。收卷、编译、持久队列、直播与固定发布已接入，完整私有备份的新目录恢复及实际进程中断 / 断连恢复通过阶段检查；全部异常状态、最终质量与完整交接仍待验收。原规则引擎不依赖 UI；浏览器只绘制已确认的帧和派生视觉字段。

v0.1 runner 在单局结束后才落盘完整 Replay。v0.2 已增加初始化完成、逐 Tick 完整结算和 result 的记录观察接口及增量持久输出，并通过固定旧 WASM / Seed 的参考比较与实际直播检查。API 与浏览器断连不改变动作或引擎推进。

元数据索引提供检索与作业状态，原始 manifest / schedule / Replay / report 仍是证据。编译、比赛由独立 worker 处理；停止调度在单局边界生效，单局中断恢复从相同输入的 Tick 0 重跑，不假定保存了 WASM 内存。

v0.2 将改变 runner 源码哈希，必须创建新运行清单。旧 v0.1 证据保留原样，旧世界 Replay 可读；精确 Bot 重跑旧证据使用旧冻结源码环境。UI 版本与规则、SDK、报告版本分层标记。

新增验收覆盖旧数据导入、结算兼容、增量直播、断连补帧、60 分钟冻结、作业恢复、报告一致性、发布过滤、浏览器操作、视觉和性能。完整清单见 [DELIVERY_v0.2.md](../DELIVERY_v0.2.md)，前端质量标准见 [视觉与交互规范](./09-v0.2-frontend.md)。
