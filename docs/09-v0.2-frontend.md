## 设计目标

观众打开页面后应知道谁在比赛、当前发生了什么、最终为什么赢或平。研究者可以逐 Tick 核查事实，主办方可以从同一产品完成收卷和组织比赛。

视觉方向固定为“竞技转播台”：舞台感来自地图、排版、对抗标识与节奏，避免用大量装饰抢占比赛空间。每个页面服从同一设计系统；表单和错误页同样纳入视觉交付。

### 将视觉目标落实为开发要求

| 用户要求 | 具体落实方式 | 评审依据 |
| --- | --- | --- |
| 功能齐全 | 观众找比赛、播放 / 检查、换边 / 批次比较；主办方收卷到发布及异常恢复均有连续入口 | 使用真实数据完成核心体验任务，不依赖临时补步骤 |
| 交互体验优秀 | 控件就近、状态可理解、操作有反馈；刷新 / 返回保持上下文；键盘与触控可完成主要任务 | 逐项操作走查、窄屏检查、失败恢复和性能测量 |
| 审美顶级 | 地图成为视觉焦点，字号 / 留白 / 数字对齐有明确层级；实体可辨认，动效克制且不遮挡事实 | 关键页面方案、真实状态截图和记录在案的人工评审 |

先评审大厅、观赛、批次分析和主办方工作台的真实数据方案，观赛页同时给出桌面与手机布局。每个阶段同时检查路径、信息层级与视觉一致性；视觉问题进入修正清单，与功能问题一起推进。

## 核心体验走查

用实际参赛数据完成以下任务；记录操作入口、完成结果和遇到的问题。发现依赖命令行补步骤、无法返回上一步或状态解释缺失时，视为体验断点。

| 用户任务 | 完成时应得到的结果 |
| --- | --- |
| 首次进入并找到可看的比赛 | 大厅明确区分正在运行与历史对局，有可直接进入的观赛入口；无数据时提供下一步 |
| 看懂当前局面 | 首屏辨认双方、槽位、地图、当前 Tick、播放位置与执行状态；图例和说明可查 |
| 解释一次死亡或连锁 | 从事件直接定位精确帧，检查坐标、owner、到期时间和结果；暂停后信息仍可读 |
| 从单局判断配对表现 | 能进入换边局和所属批次，看到样本数、胜负平与区间，理解一局不等于总体实力 |
| 刷新、返回或暂时断连 | URL 定位与筛选可恢复；保留最后确认帧，恢复后无重复帧或跨尝试拼接 |
| 组织一次赛事 | 从单份源码收卷到资格、开赛、监看、停止 / 恢复与发布，每步有状态、结果和错误恢复动作 |

默认页面先呈现观众需要的内容，fuel、原始哈希和日志放入可展开的检查区。专业细节保持可追溯，初次观赛不要求用户先理解它们。主要操作就近出现且有文字名称；所有异步操作有处理中、成功和失败反馈。

### 默认观赛体验

大厅首屏突出可立即观看的真实比赛；没有正在运行的对局时，提供清晰的历史回放入口，不能只剩作业列表或空的直播区域。可由主办方指定代表性历史对局，显示参赛者、结束原因和所属批次；工程 Baseline 与真实模型参赛者使用明确的来源说明。

进入历史对局默认展示初始状态与显眼的播放入口；精确帧链接优先恢复指定位置。进入正在运行的对局默认跟随最新，用户暂停 / 回看后保留其位置，并明确区分播放帧和服务器执行进度。首次使用可以查看简短图例，不通过强制教程阻挡观赛。

赛后提供直接通往关键事件、换边局和批次结果的入口。胜者 / 平局及原因先用普通语言说明，随后允许展开规则、动作、fuel 和证据。基础设施失败呈现未完成事实和恢复状态，不展示胜利庆祝。

观众任务和主办方任务分别设置主要操作：观赛页以播放、检查、比较为中心，管理页以收卷、开赛、停止 / 恢复为中心。比赛身份、返回批次和当前状态跨页面保持一致，避免看完一局后失去上下文。

## 信息架构

| 页面 | 核心内容 | 主要操作 |
| --- | --- | --- |
| 比赛大厅 `/` | 当前比赛、排队 / 历史比赛、批次列表、简明成绩 | 进入观赛、筛选、跳到批次 |
| 观赛 `/matches/:id` | 中央棋盘、双方信息、播放控制、事件与检查器 | 播放、定位、检查、换边局、全屏、导出 |
| 批次 `/tournaments/:id` | 冻结范围、进度、配对矩阵、榜单与案例 | 进入对局、筛选、查看区间、停止 / 恢复 |
| 参赛者 `/entrants/:id` | 模型 / 提交身份、资格状态、参与批次、行为统计 | 看比赛、查看冻结证据 |
| 主办方 `/manage` | 收卷会话、提交、作业、单局 / 批次创建 | 导入、交卷、编译、启动、恢复、发布 |

主办方写操作集中在管理入口，普通观赛操作不会触发编译、比赛或文件覆盖。v0.2 是本地应用；区分入口服务于使用清晰度，不宣称已经有远程多用户权限体系。

页面 URL 保存筛选及 `frame` 定位。直播和 Replay 不做两套互不兼容页面，状态标签标明“直播”“回看”“回放”“等待数据”“中断”。浏览器刷新和返回后恢复选择与位置。

## 桌面布局

观赛页顶栏显示双方名称、提交版本简写、比分 / 状态、批次入口。棋盘是主区域；右侧依次是选中对象、当前动作、事件列表；底部是控制栏与带事件标记的时间轴。

地图保持 13:11 的格子比例，格子必须是正方形，不被侧栏挤压变形。宽屏时舞台占主要空间，信息侧栏可收起；全屏仍保留简洁状态条、控制栏与退出按钮，不能只剩无法操作的 Canvas。

大厅以当前可观看对局作为首要内容，下方是批次和历史比赛。大量历史对局用分页 / 列表，而不是堆满同样大小的卡片。榜单数字对齐，图表和矩阵可点击到对应对局，并提供文本 / 表格视图。

## 手机与平板

- 390px 宽时采用单列：双方简卡、棋盘、控制、详情标签页；不依赖 hover 展示信息。
- 768px 平板提供可折叠详情；1280px、1440px 桌面呈现完整侧栏。各尺寸都需真实数据截图。
- 触控目标至少 44 × 44 CSS px。时间轴可触控拖动，重要操作不只藏在小图标中。
- 宽矩阵在自己的容器内横向滚动，不能让整个页面出现横向溢出。
- 移动端依然保留逐 Tick、对象检查、事件跳转与状态解释，不退化为只能观看的动画。

## 统一设计系统

以下是首版视觉基准，实现时集中为 tokens；微调须同步整套页面并记录，不能各页面独立调色。

| Token / 元素 | 基准 | 用途 |
| --- | --- | --- |
| 页面背景 | `#10151C` | 舞台外背景 |
| 信息表面 | `#1B242D` | 控制、详情与表格 |
| 主文字 | `#F3F1E9` | 骨白，标题与关键数字 |
| 次级文字 | `#A6B0BA` | 注释与次级信息 |
| 主操作 / 一方标识 | `#69DCC9` | 青绿 |
| 另一方标识 | `#EFB95B` | 暖金 |
| 错误 / 故障 | `#E97975` | 与玩家身份分开解释 |
| 边线 | 低对比灰蓝 | 网格、列表、信息层级；不可替代文字 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px | 统一布局节奏 |
| 圆角 | 小控件 6px、面板 12px | 限制胶囊泛用，地图仍为方格 |
| 字体 | 本地可用中文无衬线；数字等宽 | 中文标签稳定，比分与 Tick 不抖动 |

同一批次中参赛者的标识保持稳定，不随出生位交换。全产品多参赛者使用统一扩展色板；单局双方还需通过编号、形状、轮廓区分，不能仅靠颜色。出生槽位明确显示 0 / 1，与模型身份分开。

标题、正文、标签、数字、代码分别有字号与行高层级。避免全页大写、装饰性渐变文字、满屏发光和无意义的玻璃面板。棋盘的层次靠地形形状、边缘与有限阴影建立，不添加会改变格子辨认的纹理。

基础资源采用 CSS、SVG / Canvas 和本地字体；新增图形 / 音效须有来源与许可记录。页面不能依赖外部字体 CDN 才能正确显示。字体 fallback 需纳入截图检查。

## 棋盘视觉语言

| 对象 | 呈现要求 |
| --- | --- |
| 道路 | 低对比方格底面，保留清晰坐标对齐 |
| 硬墙 | 完整块体、稳定轮廓；不可与软墙混淆 |
| 软墙 | 分段 / 砖纹形状，销毁后变道路 |
| 玩家 | 独立标记、身份颜色、编号、方向反馈；不覆盖其他实体信息 |
| 炸弹 | 炸弹形状、owner 标记、到期 Tick / 剩余 Tick；脚下炸弹也可辨认 |
| 爆炸 | 按实际事件覆盖格显示；硬墙不覆盖，链式触发可检查 |
| 死亡 | 同 Tick 死亡同时呈现，故障淘汰和爆炸死亡有不同解释 |
| 选中对象 | 清晰轮廓 / 坐标，检查器与事件同步 |

图层顺序为地形、辅助格线、炸弹、玩家、实际事件效果、选择标记。玩家与脚下炸弹重叠时，用偏置小标记 / 徽章保留两者信息，不能将炸弹完全藏住。

移动插值仅连接已确认的起点与终点。失败移动不越墙、穿过玩家或短暂交换位置。爆炸效果来自真实覆盖集合，不让特效越过墙；软墙清理显示在爆炸阶段之后。

暂停或逐帧时，可以保持“本 Tick 爆炸事件”的可视叠层帮助检查，但须标明它是当前事件，不是下一 Tick 仍存在的火焰。隐藏事件叠层后，棋盘应精确对应当前帧世界状态。

本版默认不添加预测危险区。到期时间是事实，未来对手动作和新放弹不是事实；以后增加预测时须单独标记并说明假设。

## 播放器契约

**帧定义：**第 0 帧是 header 中初始化处理后的 `initial_state`；第 k+1 帧是 Tick k 的结算后状态。时间轴范围为 0～已完成 Tick 数，不把结算后 `state.tick` 当作刚发生的 Tick。

界面分别显示“初始状态”“Tick k 已结算”和“下一 Tick k+1”。炸弹剩余时间采用当前帧状态的下一结算 Tick 计算；本 Tick 已爆炸的炸弹通过事件检查，不假装仍属于状态中的炸弹。

| 控件 / 操作 | 行为 |
| --- | --- |
| 播放 / 暂停 | 只改变本地播放；完成时停止在结果帧 |
| 前 / 后单步 | 精确移动一帧，清理前一帧动画残留 |
| 首 / 尾 | 初始状态 / 最后已接收状态；0 Tick 局也可操作 |
| 变速 | 0.25 / 0.5 / 1 / 2 / 4 倍；默认 1 倍为每秒 4 个 Tick |
| 时间轴拖动 | 拖动时暂停并直接定位；UI 与对象信息同时更新 |
| 事件定位 | 死亡、爆炸、连锁、运行故障等跳到精确事件帧 |
| 最新状态 | 直播落后时显示“回到最新”；追上后继续跟随 |
| 双方检查 | 当前坐标、存活 / 死亡、动作、炸弹、fuel、故障计数 |
| 格子 / 炸弹检查 | 坐标、地形、炸弹 owner / 到期时间及当前事件 |
| 换边对比 | 打开同地图同配对的另一局；按相同 Tick 定位并注明双方可能不同长度 |
| 分享 / 导出 | 复制本地对局与帧链接、PNG、允许发布的 Replay / 报告 |

默认观赛音效关闭。若增加音效，所有页面共用静音设置与本地许可资源；浏览器不能自动播放有声内容。音效不是本版完成的阻断条件。

键盘：Space 播放 / 暂停，左右箭头逐帧，Home / End 首尾，F 请求全屏，Esc 退出全屏 / 关闭弹层。输入框聚焦时不抢占这些快捷键；按钮显示提示，键盘焦点始终可见。

## 直播状态与误差处理

直播数据可以快于正常播放，服务器不为某个观众放慢模拟。播放器缓冲已完成帧，不虚构未提交帧；“直播”表示对局正在运行，不保证所有观众都处于最新帧。

到最新且无新帧时显示等待数据。断连时保留最后确认状态，显示“连接中断，正在恢复”；补齐序列后继续。缺帧不插值跨过，不在还未收到 result 时提前宣布获胜。

批次进度、对局执行状态与播放器进度分别展示。播放暂停不显示为比赛暂停，宿主 watchdog 故障不包装成 Bot 超时胜负。

结束层提供胜者 / 平局、结束原因、结算次数、双方死亡 Tick 和下一步入口。双方同 Tick 死亡、500 Tick 上限、初始化结束和基础设施失败各有明确文案；基础设施失败没有正式胜者。

## 非理想状态也是完整设计的一部分

必须设计并实现：首次无数据、导入中、排队、编译中、资格失败、未交卷、0 Tick 对局、播放完成、直播等待、断连、服务不可用、文件损坏、未知 schema、不完整批次、空筛选结果、长名称与日志溢出。

错误说明发生了什么，给出可执行恢复动作；不只显示红色 Toast。日志可折叠、复制且保留原文；模型输出 / 名称作为文本呈现，不能插入 HTML。

### 逐页状态覆盖

下表是后续实现与走查任务，不是完成声明。正常页面已存在，也须和异常状态一起使用同一套组件、排版及反馈方式。

| 页面 | 必须覆盖的状态 | 用户应能执行的下一步 |
| --- | --- | --- |
| 大厅 | 首次无数据、加载、空筛选、排队、正在运行、结束、失败 / 中断、服务不可用 | 清除筛选、进入真实回放、重试加载；主办方可去管理入口建立比赛 |
| 观赛 | 初始帧、0 Tick、活动播放 / 暂停、直播等待、回看、断连 / 恢复、新尝试、正常胜负 / 平局、基础设施失败、对象不存在 | 播放 / 检查、回到最新、定位事件、进入换边 / 批次；失联时保留已确认画面 |
| 批次 | 封存、排队 / 运行、停止 / 中断、失败、不完整、完成、已发布、样本不足、并列 | 查看允许访问的进度 / 单局、比较案例；主办方恢复或发布，不完整时解释为何没有正式榜单 |
| 参赛者 | 未交卷、已冻结、编译 / 资格处理中、资格失败、资格通过、暂无比赛、历史导入身份、长名称 | 查看身份与允许访问的诊断、进入已有对局；明确工程 Baseline / 模型提交 / 历史身份来源 |
| 工作台 | 未解锁、空会话、计时中、提前冻结、截止 / 逾期、上传 / 导入中、损坏文件 / 未知格式、排队 / 编译、失败、停止 / 恢复、发布 / 备份 | 明确截止与冻结结果，查看原始错误；按实际状态重试、继续调度或导出，不能覆盖正式源码 |

全站同时检查长名称、长日志、满数据、窄屏、焦点和返回导航。封存状态解释何时可以观看，不显示已受保护的地图；页面访问不存在的资源须有明确提示和返回入口。

每个检查条目记录页面 / 资源、状态构造方法、尺寸、操作结果、截图及未解决问题。优先使用真实任务与已验证 Replay；需要构造异常时记录注入方法，不把演示数据或脚本注入成功当作真实比赛证据。A05 按完整状态覆盖判定，A04 另含可访问性操作验证。

## 可访问性与动效

普通正文与背景目标对比度至少 4.5:1，必要的组件边界 / 大字至少 3:1；实现后实测，不以色值表代替结果。状态同时用图标 / 文案表达。

Canvas 外提供 DOM 中的玩家状态、事件列表与选中格子文本，键盘能完成主要操作。播放的实时状态不逐帧轰炸屏幕阅读器，仅对用户操作和关键状态变化进行适量提示。

支持 `prefers-reduced-motion`，减弱 / 关闭位移和爆炸闪动；任何模式都不能高频闪烁。非比赛页面动效以 120～200ms 的状态过渡为主，不用每个面板入场动画拖延操作。

## 视觉与体验验收方法

### 设计与实现评审顺序

1. 先确定共用 tokens、排版、身份标识、状态语言，以及棋盘实体与事件图层。
2. 用同一组真实比赛审查观赛页桌面 / 手机方案和大厅入口，完成从找比赛到解释关键事件的路径。
3. 将设计扩展到批次、参赛者和工作台，检查跨页面导航、报告关联与收卷 / 运行操作。
4. 补齐空数据、长名称、满数据、失败、断连和终局；实际检查键盘、触控、全屏、减少动效与性能。
5. 保存最终截图、核心操作录屏及人工问题 / 修正记录，再按根目录交付清单验收。

沿用已经实现的页面和组件逐步修正。每轮评审同时检查审美、操作与事实表达；只修改首页或只给观赛棋盘换皮，不构成统一前端完成。

开发起步先用真实 Replay 做大厅、观赛、批次和收卷页的高保真方案；至少观赛页包含桌面和手机。定下 tokens、图层与控制行为后再扩展，不能用默认组件库主题作为最终设计。

最终人工走查覆盖 390 / 768 / 1280 / 1440px，以及短 / 长名称、空 / 满数据、故障、平局和正常胜负。存档真实页面截图和核心操作录屏，并记录问题与修正。

| 维度 | 通过标准 |
| --- | --- |
| 一致性 | 页面共用 tokens、字体、按钮、状态、表格和事件语言，无临时风格页面 |
| 比赛辨认 | 任意静止帧可区分道路、两类墙、双方、炸弹与实际事件；换边不混淆身份 |
| 信息层级 | 地图与双方状态优先，次级日志可收起；数字与长名称不破坏布局 |
| 交互 | 核心操作有反馈，URL 恢复、触控、键盘、全屏和错误恢复实际可用 |
| 规则真实 | 逐帧与 Replay 对齐；0 Tick、失败移动、连锁与并列死亡通过检查 |
| 完整状态 | 无数据、加载、失败、断连、完成与不完整结果都有设计和实现 |

性能目标在记录 CPU、内存、浏览器及窗口尺寸的验收机器上测量：本地 500 Tick / 不超过 16 MiB 的 Replay 导入后 1.5 秒内呈现初始棋盘，已加载帧跳转 100ms 内完成；常速播放目标 55 FPS 以上，后台编译 / 单个比赛作业时仍可操作。若未达目标，保留测量与优化记录，不能宣称已通过。

视觉质量最终需要人工判断，不以“用了 Canvas”“测试全绿”证明审美。未完成上述方案、真实数据走查与修正证据时，不能勾选前端整体交付。

走查记录逐页列出截图、问题、严重程度、修正和复核结论。身份 / 状态误导、规则呈现错误、核心操作受阻、信息被遮挡或窄屏整页溢出属于交付阻断；排版、留白、文字密度、图标、动效与视觉一致性也必须逐项检查。人工评审结论标明评审者和范围；“审美顶级”是设计追求，不能由自动化脚本或未经记录的主观声明判定完成。

### 最终审美评审的具体检查

| 检查重点 | 审查问题 | 修正要求 |
| --- | --- | --- |
| 舞台与信息层级 | 首屏是否突出棋盘、双方与主要控制？正文 / 注释 / 数字是否有层级？ | 调整布局和密度；桌面主要控制不被大棋盘推离视口，手机不压缩辨认空间 |
| 版式细节 | 标题、列、数字、标签是否对齐？中文换行、留白和长名称是否自然？ | 统一字号、行高、间距和收缩规则，保留关键身份与状态信息 |
| 视觉一致性 | 大厅、观赛、榜单、表单、日志、空态与错误页是否属于同一产品？ | 修正局部临时色值 / 控件 / 图标 / 文案，更新共用 tokens 和组件 |
| 操作连贯性 | 关键事件、换边、返回批次是否容易找到？操作反馈会不会遮挡画面或抢走焦点？ | 维持上下文、就近放置动作；加载 / 错误 / 完成反馈与同类组件一致 |
| 实体与动效 | 暂停时能否看清墙、玩家、脚下炸弹和事件？移动是否顺滑，减少动效是否仍可读？ | 修正遮挡与插值；效果服从真实状态，保留静止画面的解释能力 |

最终记录至少包含评审者、页面 / 状态与尺寸、截图、问题级别、修正位置和复核结论。交付阻断问题须解决后再验收；非阻断问题也须明确处理结论。自动截图、对比度和性能报告供评审参考，人工视觉结论单独记录到 [迭代记录](./11-v0.2-design-review.md)。
