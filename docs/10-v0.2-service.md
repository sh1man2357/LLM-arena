# v0.2 本地服务与数据架构

状态：目标架构与接口契约。收卷、编译、持久队列、比赛增量记录、通用旧批次导入、固定公开发布、公开 Replay 再导入及完整私有备份 / 新目录恢复已有实现，并通过阶段真实流程检查；完整故障路径与最终验收仍待完成。实际状态见 [交付标准](../DELIVERY_v0.2.md)，产品范围见 [产品规划](./08-v0.2-plan.md)。

## 系统边界与技术选择

保留现有 Python 规则、SDK、Wasmtime 和报告模块，在其外增加本地服务与浏览器客户端。首个支持环境仍为 Windows x64；不在本轮更换编译器或 fuel 配置。

| 层 | v0.2 实现方向 | 原因 |
| --- | --- | --- |
| 前端 | React + TypeScript，Vite 构建 | 页面与播放器状态可组织为明确组件与类型 |
| 比赛场景 | Canvas 2D；信息与控制使用 DOM / CSS | 13 × 11 网格不需 3D 引擎；便于逐帧精确呈现 |
| 本地 API | FastAPI，版本化 `/api/v1` | 复用 Python 核心并提供类型校验 / OpenAPI |
| 事件传输 | HTTP 查询 + SSE | 浏览器操作通过 HTTP，服务单向推送已提交状态与作业进度 |
| 作业执行 | 持久队列 + 独立子进程；默认同时一个计算作业 | 编译和比赛不占用 API 请求线程，保留内存与进度边界 |
| 元数据 | SQLite，Python 标准库访问；有迁移版本 | 本地持久状态与单写入协调，不引入外部数据库服务 |
| 原始证据 | 内容哈希标识的文件 + 原有批次目录 | 保留可独立审计的源码、WASM、Replay 和报告 |

这是项目实现选择；框架能力依据 [React TypeScript 文档](https://react.dev/learn/typescript)、[Vite 构建文档](https://vite.dev/guide/build)、[FastAPI 后台任务说明](https://fastapi.tiangolo.com/tutorial/background-tasks/) 与 [MDN SSE 文档](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)。SSE 用于单向通知；编译 / 比赛的持久、恢复和子进程管理由项目实现，不假定普通后台回调自带这些能力。

已提交前端 `web/package-lock.json` 与服务 `requirements-service.lock`；运行版本另见 `tools/runtime-lock.json`。独立目录安装与一键启动已通过阶段验收，见 [安装证明](../artifacts/acceptance/v0.2-development/checks/clean-room-ui.json)，实际中断恢复与整版交接仍待完成。开发用 Vite 服务与发行构建分开；正式本地启动由 Python 服务提供已构建静态文件与同源 API。

`web/` 放客户端，`service/` 放 API / 索引 / 作业 / 适配器，`artifacts/local/` 放数据库和作业产物。目录已有实现；本地产物不作为公开源码提交。

## 数据来源与索引

Replay、冻结 manifest、schedule、result 和经过校验的 report 是比赛证据来源。数据库负责身份、查询、作业与发布状态，不自行生成另一套评分。比赛索引可从原始产物重建；收卷时间、作业状态和发布记录作为持久元数据同时导出备份，不能声称仅凭 Replay 就能还原这些记录。导入失败不能留下看似成功的比赛记录。

| 实体 | 必要字段 / 关系 |
| --- | --- |
| 收卷会话 | ID、模型 / 参赛身份、task_hash、发卷与截止时间、最终收卷时间、时间记录来源、状态 |
| 提交 | ID、会话、源码哈希、原始名称、冻结时间、是否逾期、编译日志、WASM 哈希、资格状态 |
| 参赛者 | 唯一 ID、显示名称、模型标识、冻结提交、Baseline 标识 |
| 批次 | ID、参赛池、manifest / schedule / cases 哈希、版本、状态、预期 / 已完成局数、披露状态 |
| 单局 | ID、批次 / case / 换边标记、槽位映射、Replay / result 哈希、结束原因、完整性 |
| 作业 | ID、类型、输入快照、幂等键、状态、进度序号、诊断、产物、执行尝试历史 |
| 发布记录 | 批次 / 单局、收卷窗口关闭证据、允许字段、披露时间、公开副本哈希 |

UI 和 API 中的模型名称是展示字段，绝不作为提交唯一键。换边时通过 entrant_id 与 slot 显式关联；64 位 Bot Seed 保持 16 位小写十六进制字符串，不转成 JavaScript Number。

收卷会话从主办方确认模型收到任务时记录的开始时间起 60 分钟，无 token / 轮数配置。若外部对话收卷后再导入，保留真实接收时间与来源，导入时间不能伪装为交卷时间。程序接收源码以服务端收到完整源码并接受最终交卷请求的时间为准，仅开始上传不算交卷；浏览器倒计时是该截止时间的展示，断连和刷新不重置。

到期后新源码可留作逾期记录，但不能覆盖已冻结正式提交。编译耗时可以在交卷后发生，因为冻结的是截止前收到的源码；不允许因编译失败回到收卷状态继续修改。

## Replay 适配与忠实渲染

支持现有 `schema_version = 1` 的 header / tick / result，保留原始文件和哈希。适配器派生 UI 帧、事件索引、字段标签与公开副本，不能覆盖原始 Replay。

第 0 帧为初始化后的 initial_state；第 k+1 帧为 Tick k 的结算后状态。爆炸阶段覆盖格等视觉事实由 Python 适配器调用同版规则的纯结算 / 世界验证能力派生，和记录对比后输出。浏览器不重新发明移动、连锁和软墙传播规则。

若现有事件不含某个视觉字段，派生字段标为派生，并记录适配器版本与原始 Replay 哈希。无法验证的 Replay 可进入“未验证回放”检查视图，不能进入正式成绩；损坏、缺帧和未知 schema 显示明确错误。

0 Tick 对局也有初始帧与终局，直播必须在初始化淘汰处理完后发布初始帧，不提前暴露后来会修改的 header。

## 从赛后文件到真实直播

v0.1 的 `run_match` 在内存中收集整局记录，结束后才写 Replay；读取既有完整文件只能实现赛后回放，不能宣称是直播。v0.2 已实现记录观察接口与增量持久输出，基本真实直播流程通过；断连补帧、attempt 切换和完整故障恢复仍需验收。

v0.2 给 runner 增加可选的记录输出 / 作业观察接口：初始化完成、每个 Tick 完整结算、result 完成后分别提交对应记录。观察接口不能改变动作、引擎顺序或比赛随机性。

每局由一个 worker 顺序执行，先将完整记录写入可恢复的 append-only 临时日志并分配单调序号，再让 API 发布已提交的完整行。读端不读取半行。局结束后完成原格式 Replay、result、哈希与校验，再把单局纳入批次有效结果。

临时日志用于进度和诊断，不因只有几帧就成为有效成绩。worker 在单局中途失败时，这次尝试保留为中断 / 失败，恢复需按同一输入从 Tick 0 重跑该局，不能假装已经保存 WASM 内存检查点。每次尝试有自己的 attempt_id。

输出端失败与 Bot 故障分开：持久写入失败使该局 / 作业基础设施失败；浏览器断连不会影响计算；慢观众可丢弃传输缓冲并通过 HTTP 补取持久记录，不阻塞 runner。

单局创建可由主办方选择运行节奏：`tick_interval_ms` 为 0、50 或 250，默认 50，即最多每秒 20 次结算；全配对批次默认尽快计算。worker 在提交完整 Tick 后等待该间隔，不将等待纳入 Bot fuel 或世界状态，不跳 Tick、不按墙钟计算位移，也不跟随观众的播放 / 暂停。节奏是该作业的冻结输入；界面明确区分运行节奏与播放器倍速。旧参考逐记录比较同时覆盖观察接口与宿主等待。

## 作业与恢复

状态为 queued、running、stop_requested、stopped、interrupted、succeeded、failed。停止调度在当前单局完成后生效；单局播放控制不改变作业状态。

请求创建编译 / 比赛作业返回 job_id，客户端通过查询与 SSE 观察，不等待整场比赛的 HTTP 响应。写操作使用幂等键；重复点击或请求重发不能重复开赛或重复收卷。

默认一个编译 / 比赛计算作业，其他排队。每个作业携带冻结输入、版本和哈希；请求参数不能直接成为 shell 字符串，启动子进程使用参数列表。

重启后检出遗留 running 作业并标 interrupted，核对完成产物后才允许恢复。批次恢复复用现有调度与缓存校验，重试仅针对失败尝试并保留旧日志。不完整批次不能发布正式汇总。

当前实现对数据目录持有 worker 文件锁；作业与所属批次在同一 SQLite 事务创建。状态认领、停止请求、进度和披露更新采用事务读写，避免相互覆盖。幂等键校验原始请求，重发时复用第一次生成的案例和资源 ID，而不是重新抽取 Seed。服务关闭终止其自有 worker 进程树，编译子进程也在同一生命周期内。

服务启动 / 关闭负责 worker 生命周期，不遗留后台窗口或孤儿子进程。启动脚本默认只显示必要入口；需要后台启动时采用 Windows 隐藏窗口方式。

## API 契约范围

下表定义路由方向，实际字段需在第一阶段以 OpenAPI 与固定样例提交。分页、错误和事件结构必须统一，不允许前端直接读取任意宿主文件路径。

| 接口 | 用途 |
| --- | --- |
| `GET /health` | 服务版本、工作区状态、依赖就绪情况 |
| `GET /api/v1/entrants`、`GET /api/v1/entrants/{id}` | 参赛者、资格、冻结身份 |
| `POST /api/v1/sessions`、`GET /api/v1/sessions/{id}` | 60 分钟收卷记录与截止时间 |
| `POST /api/v1/sessions/{id}/submit` | 接收最终单文件源码并冻结 |
| `POST /api/v1/imports` | 异步导入预注册的 v0.1 参考归档 |
| `POST /api/v1/imports/replay`、`POST /api/v1/imports/archive` | 上传原始 JSONL Replay / ZIP 批次；批次返回持久作业 |
| `POST /api/v1/submissions/{id}/compile` | 异步编译与资格检查 |
| `POST /api/v1/matches`、`POST /api/v1/tournaments` | 根据冻结产物创建计算作业 |
| `GET /api/v1/matches`、`GET /api/v1/matches/{id}` | 筛选对局、读取状态与终局 |
| `GET /api/v1/matches/{id}/frames?after_seq=…` | 查询已提交帧并补齐缺口 |
| `GET /api/v1/tournaments/{id}`、`GET /api/v1/tournaments/{id}/report` | 批次范围、进度与校验报告 |
| `GET /api/v1/jobs/{id}`、`POST /api/v1/jobs/{id}/stop`、`POST /api/v1/jobs/{id}/resume` | 作业状态、边界停止与恢复 |
| `GET /api/v1/events` | 单个实例的 SSE 事件流，可按资源订阅 |
| `POST /api/v1/tournaments/{id}/publish` | 校验收卷关闭与成绩完整性，生成公开视图 |
| `GET /api/v1/exports/{id}?kind=replay/report/publication` | 下载公开 Replay、报告或固定发布清单，校验已归档副本哈希 |
| `POST /api/v1/backups`、`GET /api/v1/backups` | 主办方异步创建 / 查看完整私有备份，不公开宿主路径 |
| `GET /api/v1/backups/{id}` | 主办方下载私有 ZIP，校验固定归档哈希 |

响应包含资源版本、状态和关联 ID；错误为稳定 code、可读 message、必要 details。作业创建通常返回 202，冻结 / 截止 / 状态冲突返回 409，超大源码返回 413，字段不合法返回 422；不得用 200 成功包装失败。

SSE 包含 event_id、resource_id、attempt_id、seq、type 和 payload。event_id 用于连接恢复，seq 用于单次对局帧去重；重跑不能拼接到上一次尝试的帧序列。客户端发现缺口先补取，历史保留不足时返回 resync_required 并重读快照。

SSE 只是通知与增量，HTTP 持久数据是恢复依据。报告产生前只推送事实进度，不推送未经校验的正式排名。

## 导入、发布与本地边界

导入只接受已支持的数据格式与配置的大小限制。Replay 支持至少本版 500 Tick、16 MiB 文件；源码遵循 1 MiB 原限制。大批次采用有界逐文件扫描 / 分页，不能一次把所有 Replay 和解压内容放进内存。

通过文件选择上传或主办方受控目录导入；不接受浏览器任意绝对路径或 `../` 路径。归档导入检查路径、条目数、总解压大小和哈希；名称、源码、日志当纯文本处理。原始文件不从静态根目录暴露。

当前 ZIP 上传上限为 16 MiB，最多 2,000 条目、总解压 256 MiB、单条目 16 MiB。只接受未加密 Stored / Deflate ZIP；先检查完整目录，包括 Windows 大小写重复、设备名、尾随点 / 空格、文件与目录冲突及符号链接，再有界解压。根目录需要原始 manifest、schedule、cases、results 和 replays；完整与不完整批次均按真实记录验证，不完整批次无汇总成绩。所有已提供的 Replay / result、冻结输入和可选 WASM 检查完成后，在同一事务注册参赛者、单局与批次；失败诊断和临时文件保留，但不留下成功索引。

通用导入身份由原始名称和 WASM 哈希映射，报告、对局、换边与 UI 投影使用同一映射；原始文件不改名、不改写。随归档提供的 WASM 在哈希匹配后重新资格检查；缺少 WASM 的身份只用于历史观赛。只有预注册的参考赛自动标为手写 Baseline，普通历史归档不冒充真实模型提交或 Baseline。报告验证在临时副本中运行，避免覆盖原归档中的 report。

服务默认绑定 `127.0.0.1`，生产本地页面与 API 同源，写请求校验 Host / Origin 和本地会话凭据。未知外部 Origin 不得通过宽泛 CORS 获得写能力。需要主办方凭据的原始证据读取与无需凭据的公开观赛投影分开；不能只隐藏按钮就宣称私有数据受保护。远程托管与多人认证不在 v0.2 范围。

正式隐藏批次分为 sealed、disclosed、archived：

- sealed：只有主办方可查看计算证据；面向模型 / 普通观众的接口不返回地图、Seed、源码、WASM 路径或 Replay 内容。
- disclosed：主办方已关闭这批参赛池的收卷窗口并主动开启观看 / 发布；地图视为已披露，后续不能复用为未见测试。
- archived：已完成的发布记录与公开副本固定；不能修改原始成绩。

公开投影剔除私有 Seed、宿主路径和不应公开的源码 / 日志，显式列出已披露内容。完整地图一旦可见就已泄露，去 Seed 不恢复保密性。正式直播只能在收卷关闭后开始；公开开发对局不受这个等待条件影响。

上传的历史批次也默认 sealed，直到主办方确认原参赛池收卷结束。关闭记录保存首次时间、主办方确认来源和冻结参赛者 / WASM 哈希；这是主办方声明，不是远端收卷过程的自动证明。重复关闭不改时间，也不将 archived 状态降回 disclosed。

发布重新核验原始报告和 Replay，在独立目录固定公开副本与 manifest。manifest 关联原始 manifest / schedule / results 和每局 Replay 的哈希，同时记录公开文件哈希、应用版本、披露字段和关闭 / 发布时间；不包含私有 Seed、绝对路径或源码。SQLite 事务固定 publication_id，重复发布返回首次记录。下载已归档产物先核验哈希；副本损坏返回冲突，不能悄悄重新生成并冒充原发布。公开 Replay 是 seed-free 投影，只支持世界事实展示，不能据此进行完整 Bot 重跑。

公开 `.json` 再导入支持 projection_version 1 / 2，按冻结规则重新结算帧、事件几何和结果，不相信上传的 verified 标记。导入字节哈希与声明的原始证据关联分开；原始关联标为 unverified_claim，不能凭公开文件证明来源或资格。界面标明 public_world_only、缺少 Seed 和不能重跑 Bot；不完整投影拒绝导入。操作和信任边界见 [恢复说明](./12-data-recovery.md)。

官方成绩发布要求调度 complete 且结果校验通过；中断记录可用于诊断，不作为有效排行榜。单个对局的基础设施失败仍显示失败原因，不产生虚构获胜者。

## 版本与旧证据

### 备份与恢复交付契约

备份入口已实现。备份同时包含收卷 / 作业 / 发布元数据、冻结源码与 WASM、原始比赛证据及文件哈希清单。公开报告和公开 Replay 是分发产物；完整备份包含私有输入，只向主办方提供，并在界面标明用途。单个 worker 在当前计算结束后创建备份，固定 SQLite 元数据快照并核对文件；固定期间修改 API 返回 423，观赛读取可继续。

`python -m service.backup restore` 恢复到新的数据目录，校验格式、路径与全部文件哈希，再验证 Replay、报告和固定发布后才整体注册。保留原始证据内容，调整受控文件引用，重建投影缓存并生成新访问凭据；旧运行状态转为中断，由主办方显式恢复。已验证迁移后历史观赛、冻结身份、收卷时间、发布状态和排队编译的手动恢复，失败不会覆盖现有目录。完整步骤、大小限制和实际归档证据见 [恢复说明](./12-data-recovery.md)；实际进程中断 / 继续调度仍在 C05 单独验收。

### 版本边界

区分 app_version、规则 / 地图 / SDK / 报告版本与 benchmark_id。v0.2 应用默认 ruleset=1、map_generator=1、sdk=1，旧 Replay schema 1 可读。

旧 v0.1 验收归档、manifest 与冻结提交保留原样。增加 runner 观察接口会改变源码哈希，即使游戏规则不变，也必须生成新的运行清单与批次标识，不能把新二进制 / 源码冒充旧冻结环境。

兼容性包含两部分：旧 Replay 用原版结算语义可以重建世界；新 runner 在固定输入下动作、故障、世界状态与旧参考一致。新代码的 Bot 重跑仍按新清单验收；需要精确重跑旧证据时使用旧冻结 checkout / 环境。

前端资源、UI 适配器和依赖版本进入新的 v0.2 交接清单，与比赛核心哈希分层记录。UI 的变速、动画和颜色不参与世界哈希。

## 必要工程验证

优先验证真实源码编译、旧 Replay 导入、同输入结算兼容、收卷边界 / 提前冻结、作业幂等、服务重启、断连补帧、失败不计分、公开字段过滤与完整报告一致性。纯视觉微调通过截图走查，不为每个间距写实现镜像测试。

端到端至少完成“导入 Bot → 编译 / 资格 → 单局直播 → 回放 → 全配对换边 → 报告 → 导出 / 恢复”。浏览器操作验证与已有 Python 检查共同提供证据，不能用模拟数据前端取代真实后端闭环。
