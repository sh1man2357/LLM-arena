# v0.2 视觉方案与迭代记录

这是实际实现阶段的走查记录，不代表全部 v0.2 已完成。

## 2026-10-05：历史观赛与报告页面

以 v0.1 真实证据建立大厅、观赛、批次分析、参赛者与工作台的同一套视觉。实现统一 tokens、SVG 图标、中文本地字体、Canvas 地形 / 玩家 / 炸弹图层。没有使用外部视觉素材或字体 CDN。

高保真页面由真实 Replay 驱动，不用伪造比赛数据。代表案例为 Tick 18 连锁爆炸与双方同 Tick 淘汰；报告为原始 300 局工程参考赛，明确标记手写 Baseline，不冒充真实模型评测。

走查截图位于 `artifacts/acceptance/v0.2-development/visual/`：大厅、观赛、批次与管理入口，各有 390 / 768 / 1280 / 1440px 版本。浏览器检查验证页面没有水平溢出，棋盘比例保持 13:11。

第一轮发现桌面棋盘将播放控件推到首屏以下，改为根据视口高度约束棋盘宽度；手机部分标签与触控目标偏小，增大了事件 / 格子文字、逐帧按钮和地图案例目标。第二轮截图与三条真实浏览器流程再次通过。

当前已验证：逐帧、首尾、五档速度、事件定位、键盘、格子检查、PNG、URL 刷新定位，以及矩阵 → 地图换边组合 → 换边局入口。模型收卷、编译 / 调度和真实直播正在接入；最终视觉验收还需覆盖这些流程与所有异常状态、性能和可访问性实测。

代码检查使用 `npm run build`，浏览器检查使用 `npm test`（先启动本地服务）。确切依赖见 web/package-lock.json 与 requirements-service.lock。最终交接会归档截图与检查日志，当前开发截图可由上述流程重新生成。
