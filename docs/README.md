# LLM Arena 文档入口


最终工程验收已完成，统一证据见 [整版交接](../HANDOFF_v0.2.md)。当前仅 A06 的最终真人视觉确认待完成；下文的历史推进安排不再表示其他验收未通过。

LLM Arena 让不同模型在统一开发条件下编写 Bot，冻结提交代码，再让 Bot 在未知、可复现的炸弹人竞技场中比赛。模型只参与开发，不参与正式比赛。

v0.1 规则、地图、SDK 和运行参数已经实现并完成工程验收，当前冻结清单见根目录 DELIVERY.md 与 artifacts/acceptance/v0.1-release/manifest.json。模型开发采用 60 分钟限时交卷协议；真实模型评测、多人赛制和长期 Rating 是后续范围。重要规则调整应建立新版本。

v0.2 的核心是完整观赛产品：图形直播 / 回放、统一视觉与交互、收卷、调度和分析。历史观赛、收卷冻结、异步编译、调度与真实单局直播，以及公开回放再导入 / 私有备份新目录恢复已有实现；实际进程中断 / 断连恢复和本机性能通过阶段检查，全部异常状态、完整可访问性、最终交接及人工视觉仍待完成。本文档组定义目标规格；实际实现进度与整体验收以 [DELIVERY_v0.2.md](../DELIVERY_v0.2.md) 为准。

规划阅读顺序：先看 [产品范围与开发取舍](./08-v0.2-plan.md)，再看 [核心体验与视觉标准](./09-v0.2-frontend.md) 和 [服务契约](./10-v0.2-service.md)；开发进度只在根目录交付清单汇总，设计迭代在走查记录中留证。

本版主题为“可观赛、可解释、可交接”。规划列出前端以外六组配套开发的复用基础和优先级；前端规范将功能齐全、优秀交互、审美与统一风格转为可评审要求。所有必需能力完成并通过独立交付清单后，才视为 v0.2 整版完成。

首轮评审路径为“大厅 → 真实观赛 → 关键事件 → 换边 → 批次解释”。优先打磨观赛页和大厅，再完成其余页面与全部状态；代表性对局可以手工指定，来源与完整批次可查。配套开发围绕真实收卷、运行、成绩依据、恢复和交接展开。

当前已有 28 / 29 项通过记录，共用页面方案与局部恢复见 [组件与页面状态](./17-components-and-page-states.md)，收卷 / 冻结 / 未完成排名见 [边界记录](./18-receipts-and-freezing.md)，性能与后台响应见 [实测记录](./16-performance.md)。后续按 [发布前实际投入](./08-v0.2-plan.md) 推进；页面实现及验收按 [逐页状态覆盖](./09-v0.2-frontend.md) 和最终审美检查执行。整版及人工视觉验收仍待完成。

## 决策状态

此前讨论确认的原则：

- 模型开发条件统一，正式比赛期间不调用模型。
- 使用离散 Tick；Bot 根据同一个 Tick 的状态同时提交动作。
- 使用 seeded RNG、公开开发地图、隐藏正式 Seed 和出生位轮换。
- 允许 Bot 保存内部状态，统一限制计算资源和内存。
- 核心成绩来自存活名次；击杀等统计用于解释风格。
- 准备多个 Baseline，指定一个稳定 Baseline 作为最终展示零点。
- 游戏、地图、SDK、运行时和 Baseline 必须版本化。
- 第一版完成双人比赛、换边、批量统计和 Replay。
- v0.2 以风格统一、高质量交互的观赛前端为核心，同时补全提交、调度和分析。
- 模型开发限时 60 分钟、可提前交卷，无额外 token / 轮数待填配置。

此前讨论的倾向：Bot 使用 C++20，正式比赛编译为 WebAssembly；长期 Rating 算法尚未选择。

实现时补充的地图尺寸、动作枚举、Tick 顺序、冲突处理、炸弹参数、ABI、随机算法和资源参数，已按实现决策冻结，并通过单项检查、完整批次和复现验收。它们不应被误认为此前讨论中已全部明确选择。

## v0.1 冻结默认配置

| 参数 | v0.1 建议值 | 定义位置 |
| --- | --- | --- |
| 比赛人数 | 2；协议预留最多 8 | 游戏规则、SDK |
| 地图 | 13 × 11，180° 对称 | 地图规范 |
| 初始炸弹容量 / 范围 | 1 / 3 | 游戏规则 |
| 炸弹延迟 | 放置 Tick + 4 时爆炸 | 游戏规则 |
| 最大 Tick 数 | 500 | 游戏规则 |
