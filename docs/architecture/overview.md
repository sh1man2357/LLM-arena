# 核心架构

服务端负责规则结算、WASM 执行和录像校验，浏览器负责对战配置、输入与播放。应用和命令行共用规则引擎与运行时。

| 模块 | 职责 |
| --- | --- |
| `engine/` | 炸弹人地图、世界状态、同时移动、爆炸和计分 |
| `gomoku/` | 五子棋开局、行棋、动作编码、对局与录像校验 |
| `sdk/`、`runtime/` | C++20 头文件及包装器、状态编码、Wasmtime 实例与执行预算 |
| `runner/`、`replay/` | 编译、资格检查、对局执行、实力分估计、录像验证和文本回放 |
| `service/` | Bot 快照、任务与进程管理、历史记录、帧接口和榜单 |
| `web/` | React 页面、Canvas 棋盘、播放控制及静态任务包下载 |
| `devkit/`、`tools/` | 任务书、安装入口、公开开发包构建及练习工具 |

## 数据流

1. 服务保存源码快照，后台任务使用所选游戏的 SDK 编译，并对 WASM 执行资格检查。
2. 开赛时固定参赛快照、槽位、地图或开局种子及各 Bot 种子。相同 Bot 出现在多个槽位时，各槽位使用独立实例。
3. 炸弹人先收集所有存活 Bot 基于同一世界状态的动作，再统一结算。五子棋只调用行棋方。人机模式在人的回合等待输入，在 Bot 的回合复用盘内实例。
4. 工作进程依次写入初始状态、每次结算和结果。服务将记录转换为连续显示帧，直播与历史回看使用同一接口。世界校验通过后，服务提交有效结果。
5. 榜单读取当前可统计的对局并按游戏计算实力分。五子棋 Bot 对战的两盘各有独立录像，整组满足条件才计入统计。

服务的存储与请求契约见[本地服务](service.md)。规则和统计口径见[文档目录](../README.md)。
