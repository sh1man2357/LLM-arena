# 核心架构

Python 3.12 规则引擎、Wasmtime 49.0.0 与 WASI SDK 33.0 保持原有契约。C++20 编译为 WASM，服务端按整数 Tick 结算，前端只消费已确认帧。

| 模块 | 职责 |
| --- | --- |
| `engine/`、`gomoku/` | 炸弹人同时结算；五子棋轮流落子、开局与终局 |
| `sdk/`、`runtime/` | C++ SDK、ABI、沙箱、fuel 和故障分类 |
| `runner/` | 统一编译、技术检查、单局执行与 CLI |
| `replay/` | 世界校验、Bot 重跑校验、文本观看 |
| `service/` | Bot 导入、一个计算任务、运行记录、帧读取、榜单 |
| `web/` | 首页、统一观赛播放器、榜单 |

主链路：Bot 快照 → 单局执行器 → 顺序运行记录 → 帧适配器 → 播放器。直播记录仍在增长，录像记录已结束；两者共用格式、接口与组件。

炸弹人每 Tick 给所有存活 Bot 同一快照，收齐动作后统一结算。五子棋每步只调用行棋方，动作是坐标或认输，使用独立 SDK 和协议 magic。运行记录保存初始状态、初始化、调用、动作、事件、逐步世界和终局。世界校验按游戏重新执行规则；Bot 重跑校验另需原 WASM 与相同环境。

Bot、运行和帧携带 game_id；缺省按 bomberman 解释以兼容历史数据。共用编译、沙箱、计算任务、存储和播放器，规则 / 协议 / 棋盘按游戏分派。五子棋一个任务顺序执行两盘独立记录，换色和种子冻结在任务输入中；失败 / 重启结算所有未结束记录，只有完整有效的两盘进入五子棋榜单。

核心本地数据为 Bot、运行和内部执行任务。旧会话、提交、参赛者、批次、发布与备份对象不参与新版流程；旧数据原样保留。必要输入与哈希用于快照一致性，不建设证据发布体系。

详细契约见[服务架构](service.md)，操作见[导入与观赛](../guides/organizing-matches.md)。
