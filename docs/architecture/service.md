# 本地服务与数据

FastAPI 提供同源 API 和已构建的 React 静态文件，Canvas 绘制棋盘。SQLite 保存索引与内部任务，文件保存 Bot 源码 / WASM 和顺序运行记录。默认数据目录为 `artifacts/local/`。

## 核心对象

| 对象 | 内容 |
| --- | --- |
| Bot（`bot`） | ID、游戏 ID、可编辑名称与备注、源码快照与哈希、WASM 与哈希、处理中 / 可运行 / 失败、诊断、回收站时间 |
| 运行（`run`） | 游戏 ID、参赛 Bot 及槽位、名称快照、地图 / 开局 Seed、状态、帧文件、验证结果；五子棋另有两盘关联信息 |
| 内部任务（`task`） | 编译 / 单局 / 基准准备、请求去重键、固定输入、进程执行状态 |

旧数据库沿用现有表结构，新增记录类型，与旧 `session/submission/entrant/match/tournament/job/backup` 隔离。不开启自动迁移，不改写旧记录和文件，不创建新的主办方凭据。

名称只用于展示；ID 唯一标识快照。选择参赛 Bot 的顺序就是槽位顺序。64 位 Bot Seed 用 16 位十六进制字符串存储，不转为 JavaScript Number。

## 编译与单局执行

导入将源码保存到 `bots/<id>/bot.cpp`，创建一个编译任务；自动编译并检查运行条件。基准 Bot 来自当前源码，准备后直接可选，不自动开赛。

基准 BOT 身份只依赖自身源码、实际辅助头文件、SDK、编译器与编译配置，不随对局执行器或回放代码变化。启动时复用构建输入相同且文件哈希完整的既有快照；文件损坏或丢失时重新构建。Bot 列表每种游戏只展示唯一基准的最新创建版本（含编译中或失败状态），旧 Random / Safe / Heuristic / Tactical / Search 退役并隐藏。数据库中的快照及历史对局引用保留，用户导入项不按名称合并。

SQLite 事务同时检查去重键和计算槽位，再建立任务与资源。请求重发复用首次创建的 Bot / 运行及随机输入；不同请求在计算忙时返回 409，不进入等待队列。编译与运行在独立子进程执行，API 不同步等待计算完成。

服务持有数据目录的 worker 文件锁。Windows worker 加入 Job Object 后通过 stdin 握手执行，服务退出时结束自有进程树；保留已有进程隔离机制。任务只有一次执行，失败 / 中断后不能续跑，重新导入或重新运行建立新记录。服务重启将未完成核心任务标为中断，旧任务不自动执行。

## 运行帧

worker 将 header、每个完整 tick 与 result 写入同一 `runs/<id>/frames.jsonl`，每条完整记录落盘后通知。该文件同时是实时数据源和录像，结束后不另造公开副本或另一份播放格式。

帧适配器使用现有规则重新验证状态与事件，并派生爆炸覆盖格。第 0 帧是初始化处理后的状态，第 k+1 帧是 Tick k 的结算后状态；0 Tick 结束也有初始帧和结果。

读取忽略末尾半行。完整终局通过世界校验并提交运行索引后才对外显示有效结果。帧接口支持 `after_seq`，返回连续帧游标；缺口或运行 ID 不一致要求完整快照。观赛不执行 Bot。固定运行节奏是 Tick 提交后等待 50ms，独立于浏览器播放速度。

## API

| 方法 / 路径 | 用途 |
| --- | --- |
| GET `/health` | 服务 / 构建状态 |
| GET `/api/v1/status` | 是否正在计算 |
| GET / POST `/api/v1/bots` | Bot 列表 / 上传单文件 .cpp 自动编译 |
| PATCH `/api/v1/bots/{id}` | 编辑 Bot 名称和备注，保留程序及历史快照 |
| POST `/api/v1/bots/manage` | 按 ID 批量移入回收站或恢复 |
| GET / POST `/api/v1/matches` | 分页运行记录 / 创建单局 |
| POST `/api/v1/human-matches` | 创建五子棋人机单盘，选择 Bot 和人类执子 |
| POST `/api/v1/matches/{id}/actions` | 提交指定轮次的人类落子或认输 |
| GET `/api/v1/matches/{id}` | 本局状态与结果 |
| GET `/api/v1/matches/{id}/frames` | 同一个直播 / 录像帧读取接口 |
| POST `/api/v1/matches/{id}/rerun` | 使用原 Bot / 随机输入建立新运行 |
| GET `/api/v1/leaderboard` | 已验证有效单局的本地统计 |
| GET `/api/v1/events` | SSE 状态通知，重新连接后读取快照 |

POST 运行使用 `game_id`（默认 bomberman）、`bot_ids` 和可选 `map_seed`。炸弹人支持 2～8 个槽位；五子棋固定两个槽位、可选 `opening_mode=empty|library`，自动建立两盘换色记录。允许重复 Bot ID，各槽位使用独立实例；Bot 与运行必须属于同一游戏。重跑保留整组参赛快照、开局和种子。

人机创建接口使用 `bot_id`、`human_slot=0|1`（默认 0 执黑），建立 `mode=human` 的空棋盘单盘，不创建换色组，也不进入榜单。worker 保留同一个 Bot 实例，在人类回合设置 `waiting_tick` 并等候数据库中的输入；该盘继续占用计算槽位。动作接口使用整数 `tick` 与 `action`（0～224 为格子索引，225 认输），在事务内检查运行状态、等待轮次、行棋方和空位；重复的最近一次相同输入幂等返回，冲突或过期动作返回 409，非法字段或占用位置返回 422。浏览器刷新后读取同一运行可继续，服务重启按现有逻辑中断。人机“再来一局”保留对手和执子，使用新种子建立新盘。

Bot 和记录列表支持 game_id 筛选，清空记录也保持游戏筛选范围。榜单默认为炸弹人，可选 gomoku；五子棋只统计两盘有效且未删除的完整组。GET 单盘额外返回 pair 状态和完成后的比分，帧仍是该盘独立序列。历史缺少游戏 ID 时按炸弹人读取，不重写历史文件。具体输入验证以 OpenAPI 为准。

Bot 列表默认排除回收站，`trashed=true` 返回已删除 Bot，`in_use` 表示有未结束任务引用。前端在当前游戏内搜索、筛选并按 20 个分页。PATCH 可部分更新 `name`（去首尾空格后 1～100 字符）和 `description`（最多 1000 字符，允许空串），拒绝空请求、null、游戏 / 基准身份 / 程序路径等额外字段。基准同样允许编辑名称和备注；编译中的 Bot 不允许编辑，避免与编译结果提交互相覆盖。基准以独立 `baseline_key` 识别策略、查找构建源码并选择当前参考快照，显示名称不参与这些判断；旧记录在首次编辑时固定原策略键。列表、参赛选择和榜单以独立标记显示其基准身份，0 分锚点仍绑定原 Bot ID，删除保护仍由 `baseline` 身份决定。

Bot 管理使用 `action=trash|restore` 和 1～100 个 `ids`，批量操作在一个事务内验证并提交，失败不产生部分删除。删除通过 `deleted_at` 隐藏记录；基准、编译中和正在被任务使用的 Bot 不能删除。开赛创建任务时，在同一计算槽位事务内再次检查 Bot 未删除，避免冻结快照与删除并发穿透。历史重赛也要求 Bot 已恢复。回收站 Bot 从榜单可见行移除，其历史对局仍保留并参与其他选手的实力估计；恢复后重新展示原统计，不删除任何源文件或录像。

写请求要求 `X-Arena-Local: 1`，使用 `Idempotency-Key` 防止请求重发重复导入 / 开赛。服务仅接受本机 Host，拒绝跨站 Origin 与 Sec-Fetch-Site。没有主办方 / 观众权限切换，但仍保留本机写入意图和同源边界。参数不拼接 shell 命令，浏览器不能读取任意宿主路径。
