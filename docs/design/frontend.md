# 前端体验与视觉规范

界面只保留首页、观赛和榜单；使用同一顶部导航与视觉 tokens。以棋盘和主要操作为中心，减少管理表单和技术信息。

## 页面

| 页面 | 内容 |
| --- | --- |
| 首页 | .cpp 导入与名称、Bot 状态、选择双方、可选地图 Seed、运行记录 |
| 观赛 | 双方名称 / 存活 / 坐标 / 必要故障、棋盘、时间轴、播放控制、结果 |
| 榜单 | 同分并列名次、Bot、局数、胜 / 平 / 负、平均得分和统计范围提示 |

不提供批次、参赛者详情、收卷、管理工作台、发布或备份页面。编译失败在 Bot 列表就地展示，日志可展开。运行记录直接进入观赛，分页只用于访问较旧记录。

## 统一播放器

`Viewer.tsx` 只根据运行状态和连续帧工作；没有独立直播 / 录像组件。服务端负责游戏逻辑，Canvas 仅呈现事实。

- 运行中默认跟随最新；暂停、拖动、单步或播放切换为回看。
- 回到最新恢复跟随；没有新帧时等待，不生成预测帧。
- 已结束录像初始停在第 0 帧，播放到尾停止；可重新从头播放。
- 支持首尾定位、五档倍速、全屏和基本快捷键。
- 运行结束显示结果；失败 / 中断明确说明本局不计分，保存帧仍可回看。
- 重新运行创建独立记录，不能在旧录像里混入另一轮帧。

初始帧与结算 Tick 语义一致，0 Tick 可展示。动画只连接已确认起终点；爆炸覆盖来自适配器。两种墙、双方和脚下炸弹可辨认；双方使用编号、不同形状和固定槽位颜色，不能只靠颜色。

## 视觉与窄屏

沿用深色背景、青绿 / 暖金双方、骨白正文、红色故障提示。色值集中在 `tokens.css`，场景绘制复用已有棋盘。

布局在窄屏改单列，长 Bot 名称和日志可换行；表格在自身容器内滚动。触控目标至少 44px，焦点可见，输入控件聚焦时不抢占快捷键。Canvas 外有 DOM 双方状态，支持减少动效。

## 核心走查

使用专用测试实例检查：无数据、编译中 / 失败 / 成功、运行准备、直播、回看、等待帧、断连、完成、初始化结束、失败 / 中断和空榜单。

桌面与 390px 窄屏检查棋盘辨认、操作可达、长名称、横向溢出、键盘与全屏。浏览器脚本和截图输出到 Git 忽略目录。构建通过不代替对真实运行画面的检查。
