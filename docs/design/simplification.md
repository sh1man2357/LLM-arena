# 核心功能简化方案

状态：核心改造已实施，浏览器验收中。日期：2026-10-10。按用户补充要求暂时保留榜单。

本次目标是把 LLM Arena 收敛为一个本地 Bot 对战与观赛工具：**导入 Bot，选择双方，运行一局，观看过程与结果。** 录像和直播使用同一套运行记录、数据接口和播放器。除此之外的比赛组织、成绩管理与证据发布业务从产品和实现中移除。

本文记录本轮改造范围。使用、架构与开发包文档已同步到简化后的实现；验证结果随阶段提交更新。

## 1. 唯一主流程

1. 导入 Bot，应用自动编译并检查能否运行。
2. 在 Bot 列表中选择两个 Bot，点击“运行”。
3. 直接进入观赛画面，显示正在产生的对局帧。
4. 运行结束后保留结果和录像，在原来的观赛画面回看。
5. 下次打开应用，从本地运行记录中选择一局继续观看。

用户不需要先创建收卷会话、填写模型身份、等待开发倒计时、手动冻结源码、创建批次或执行发布操作。

“运行”仅指单局 Bot 对战；“观看”指浏览这一局已经产生的帧。观看历史录像时直接读取保存的帧，不重新执行 Bot。要再次执行 Bot，明确点击“重新运行”，创建新的运行记录。

## 2. 保留与删除的边界

| 功能 | 处理 | 简化后的边界 |
| --- | --- | --- |
| Bot 导入 | 保留 | 选择文件、名称、自动编译、运行检查、成功或失败提示 |
| Bot 列表 | 保留 | 名称、是否可运行、选择双方；不建设独立身份档案 |
| 单局运行 | 保留 | 两个 Bot、固定规则、地图 Seed；运行过程异步执行 |
| 观赛 | 保留 | 棋盘、双方状态、当前 Tick、播放控制、终局结果 |
| 录像 | 保留 | 每局自动记录，本地列表打开，复用观赛画面 |
| 基准 Bot | 保留 | 使用当前源码生成，可直接选用；不自动生成大批参考比赛 |
| 游戏规则、SDK、WASM 沙箱 | 保留 | 沿用现有规则与资源限制，保证 Bot 能安全且一致地运行 |
| 收卷与开发计时 | 删除 | 无发卷记录、60 分钟倒计时、提前交卷、截止和逾期业务 |
| 正式提交与资格档案 | 删除 | 无会话、提交、参赛者三层业务对象；必要技术检查并入导入 |
| 批次、全配对、自动换边 | 删除 | 不保留赛程页、批次详情或批次调度 |
| 榜单 | 暂时保留 | 汇总本机有效单局的胜 / 平 / 负和平均得分，按 Bot 快照统计，同分并列 |
| 详细成绩分析 | 删除 | 无配对矩阵、故障率报表、地图区间或独立报告体系 |
| 封存、收卷关闭与发布 | 删除 | 无主办方 / 观众身份切换、地图披露状态、发布确认流程 |
| 公开报告和证据导出 | 删除 | 无公开副本、证据清单、发布包或独立报告体系 |
| 外部 Replay / 批次 ZIP 导入 | 删除 | 本轮只观看本机运行生成的录像，不建设归档交换系统 |
| 私有备份和恢复工作台 | 删除 | 无备份列表、备份作业、恢复向导 |
| 作业管理中心 | 删除 | 编译 / 运行状态就地展示，无通用队列、批次续跑和尝试历史页面 |
| 分享、截图、换边对比、复杂检查器 | 删除 | 不保留独立工具面板；只留下理解当前画面所需的信息 |

删除意味着后续移除对应页面、API、业务模块、专用脚本和测试，不只是隐藏入口。核心依赖须先拆开，再删除外围代码，避免把旧系统整体留在后台。

本方案中的功能删除不授权删除已有收卷、比赛或备份数据。旧数据原样保留在原数据目录，新版无需自动迁移所有历史业务对象。

## 3. Bot 导入

首轮沿用项目现有的 C++20 单文件 `.cpp` 输入和统一 SDK，导入后自动编译为 WASM。暂不新增任意语言、项目 ZIP、多文件构建、自定义编译参数或直接上传 WASM 的产品入口。

- 名称默认取文件名，用户可修改；名称不作为唯一 ID。
- 导入动作保存源码快照，编译和运行检查自动完成，不拆成多步操作。
- 检查只负责确认 ABI、初始化与运行条件，不建立“正式参赛资格”业务。
- 导入状态只有“处理中”“可运行”“失败”。失败就地显示原因和可展开的原始日志。
- 源码修改后重新导入形成新的 Bot 记录；旧录像仍引用原 Bot 快照，不被后来导入覆盖。
- 运行只读取项目管理的编译产物，不执行用户提供的 shell 命令或任意宿主程序。

单文件输入的选择是本轮收敛范围，不改变 SDK。开发任务材料可继续维护在 `devkit/`，但从主应用中移除发卷和限时评测流程；相应文档不再要求先收卷才能运行。

## 4. 界面收敛

保留首页、观赛和榜单三个视图，共用一套应用布局：

| 视图 | 内容 | 主操作 |
| --- | --- | --- |
| 首页 | Bot 列表、双方选择、本地运行记录 | 导入 Bot、运行、打开录像 |
| 观赛 | 棋盘、双方简要状态、时间轴、本局结果 | 播放 / 暂停、逐帧、倍速、回到最新、返回首页 |
| 榜单 | 已验证有效单局的局数、胜 / 平 / 负、平均得分 | 查看本地统计、返回首页 |

移除大厅 / 赛程 / 参赛 / 管理四组导航，不再让用户在工作台和观赛页之间往返。Bot 导入使用首页的小表单或弹层，失败日志也在该处查看。

运行表单只要求选择双方，地图 Seed 放在可选设置中，默认自动生成并随运行保存。规则、计算预算与运行节奏使用固定默认值；不展示“正式 / 工程比赛”、案例数量、隐藏地图、运行间隔等配置。

运行记录仅展示双方、时间、状态和本局结果，点击即可观看，不增加筛选系统、统计总览或另一层详情页。首次无数据时提供导入提示和基准 Bot，用户点击运行后才生成第一局。

榜单胜局计 1 分、平局计 0.5 分、负局计 0 分，按平均得分降序排列，同分并列；未完成、失败、中断和旧业务数据不计入。没有有效局的 Bot 不排名。每个重新运行成功的单局单独计数。该榜单只是本机运行统计，对手和局数可能不同，不作为统一评测或长期评级，不为榜单恢复批次调度。

观赛信息以棋盘为中心。双方仅显示名称、存活状态和必要故障说明；技术日志折叠显示。保留全屏和基本键盘操作，不把它们做成额外业务页面。现有棋盘渲染能力优先复用，视觉改动服务于布局减负。

## 5. 直播与录像统一

### 同一条数据链路

`两个 Bot + 地图 / 随机输入 → 单局执行器 → 顺序写入运行记录 → 帧读取接口 → 同一个播放器`

正在执行的记录会继续增长；已结束的记录不再增长。播放器根据运行状态展示“运行中”“已结束”“失败 / 中断”，不为直播和录像建立两套路由、组件、数据格式或渲染逻辑。

当前项目已经由 `web/src/Viewer.tsx` 同时承载直播与回放，`web/src/live.ts` 处理帧合并，`service/replays.py` 派生观赛帧。本轮在这些能力上简化，移除批次、发布、身份档案与复杂检查面板的依赖。

### 执行和播放各自负责什么

| 动作 | 行为 |
| --- | --- |
| 点击运行 | 服务启动一次新的 Bot 执行，自动保存初始帧、各 Tick 和结果 |
| 观看运行中的对局 | 同一播放器读取不断追加的已确认帧，默认跟随最新 |
| 暂停、逐帧、拖动、倍速 | 只改变本地播放位置与速度；服务继续运行 |
| 回到最新 | 定位到最新确认帧，恢复跟随；没有新帧时等待 |
| 运行结束 | 同一画面显示结果，可立即从头或任意已保存帧回看 |
| 打开历史录像 | 从同一帧接口读取已有记录，不调用 Bot |
| 重新运行 | 沿用原 Bot 快照和随机输入，从 Tick 0 开始，创建新记录 |

运行与播放不会共用一个可变的世界对象。游戏逻辑仍只有服务端执行器负责，浏览器仅呈现已确认事实。播放速度不进入游戏结算；不能以录制视频、预制动画或重新模拟世界替代运行帧。

### 必须保留的正确性

- 第 0 帧是初始化处理后的状态；第 k+1 帧是 Tick k 的结算后状态，0 Tick 结束也可展示。
- 只发布完整写入的帧，使用连续序号；重连补帧和去重，不跨缺口虚构动画。
- 断连时保留最后确认画面，恢复后继续读取；浏览器关闭不影响服务正在执行的一局。
- 完整结果记录到达后才展示胜负；Bot 故障沿用规则处理，服务 / 写盘失败标为运行失败。
- 服务退出导致未完成运行中断，已写入的完整帧可供查看，但不产生正常胜负。
- 不提供断点恢复或旧记录内追加重试；重新运行创建新记录，避免不同执行混成一段录像。

## 6. 实现结构

领域对象收敛为 **Bot、运行、运行帧 / 结果**。编译状态属于 Bot，执行状态属于运行；不再要求收卷会话、提交、参赛者、批次、发布记录互相关联。

| 层 | 保留职责 | 移除职责 |
| --- | --- | --- |
| `engine/`、`sdk/`、`runtime/` | 规则、地图、接口、编译契约、WASM 限制 | 本轮不修改规则和 ABI |
| `runner/`、`replay/` | 编译、技术检查、单局执行、记录、世界校验 | 全配对赛程、批次恢复、排名报告及相关 CLI |
| `service/` | Bot 导入、单局异步执行、本地索引、统一帧读取 | 收卷、发布、分析、归档导入、备份恢复和通用作业业务 |
| `web/` | 首页、观赛页、棋盘和必要播放状态 | 赛程、参赛者档案、收卷档案、管理工作台及专用组件 |
| `tools/`、`tests/`、`docs/` | 安装、开发包、清理工具与核心验证 / 说明 | 仅服务被删业务的工具、测试和文档内容 |

优先沿用现有 SQLite、本地文件存储、FastAPI、React 和 Canvas，不为简化目标更换技术栈。沿用必要的进程隔离和服务关闭处理；编译与运行仍异步执行，不占住 API 请求线程。

首轮只允许一个计算任务同时执行，忙时就地提示稍后重试，不引入等待队列或调度中心。防止重复点击 / 请求重发创建重复运行，保留必要的请求去重。刷新页面后可重新读取 Bot / 运行状态；服务重启时把遗留未完成任务标为失败或中断，不自动续跑。

内部保存 Bot 快照、WASM 哈希、规则版本、地图和随机输入，以便解释本局和再次运行；这些信息不扩展成证据审计产品。沿用当前 Replay 记录及其世界校验，去掉封存与公开投影业务，不同时维护“原始版 / 公开版”两套录像。

新版只读取自己的核心数据。首次启动不自动导入历史归档，不依赖历史验收产物，不清空或覆盖旧数据。必要的 schema 更新采用增量方式，旧业务数据可继续留存，但不恢复旧页面。

## 7. 改造顺序

1. **打通独立核心。** 导入不再依赖收卷会话；单局运行不再依赖批次、正式资格档案或发布状态，记录能独立读取。
2. **收敛前端。** 首页完成导入、选择和运行，观赛页统一处理运行中与已完成记录，移除外围导航和工具面板。
3. **删除外围实现。** 逐项检查依赖后移除收卷、赛程、报告、分析、发布、归档导入、备份恢复模块及路由。必要核心工具先提取出来，不保留不可达旧业务作为最终状态。
4. **同步维护材料。** 更新 README、使用指南、架构、开发包说明和测试；删除失去用途的操作内容与验收脚本。保留 Git 历史、现有依赖和主办方数据。
5. **验证核心闭环。** 用当前源码生成基准 Bot 和测试局，检查导入到观看全过程，以及下面的异常情况。

各阶段允许临时共存以便改造；最终交付须完成代码和文档删除，不能止于换首页和隐藏按钮。

## 8. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 全新实例 | 不需要比赛组织配置；可以导入或选择基准 Bot 并运行 |
| 导入有效 Bot | 一次导入自动完成编译与检查，成功后直接可选 |
| 导入无效 Bot | 原位置显示具体错误，失败 Bot 不能开始运行，其他 Bot 可用 |
| 单局执行 | 选择两个 Bot 后进入观赛，棋盘来自真实执行帧 |
| 直播回看 | 暂停、拖动、逐帧和倍速不影响执行；回到最新可以继续跟随 |
| 完成后观看 | 无页面或数据格式切换；结果显示正确，历史打开不执行 Bot |
| 刷新与断连 | 当前已确认帧保持可看，重连能补齐，无重复和越帧 |
| 终局与失败 | 正常胜负、同 Tick 死亡、Tick 上限、初始化结束、运行中断均如实展示 |
| 再次运行 | 创建独立记录，旧录像及引用的 Bot 内容保持稳定 |
| 榜单 | 有效单局按快照身份汇总、同分并列；失败和中断不计分 |
| 范围检查 | 界面和 API 不再提供收卷、批次、详细分析、发布、归档交换和备份业务 |

实现后按项目约定执行 Python 单元测试、文档检查、前端构建和协议测试；浏览器走查只使用专用测试实例。删除外围专用测试时保留并调整规则、沙箱、单局执行和帧一致性的测试，不以减少测试数量作为简化成果。

本轮完成的标准是：用户只需理解“Bot”和“一次运行”，就能完成导入、对战、观看和回看。新增能力必须直接服务这条流程，不能重新引入比赛管理平台。
