# 单局得分与本地榜单

本文件主体描述炸弹人。五子棋使用独立榜单，只统计完整有效的两盘换色对战；每盘胜 1、平 0.5、负 0 分，并显示执黑和执白成绩，详见[五子棋计分与契约](gomoku.md)。

项目支持 2～8 人各自为战，使用归一化名次分，暂时提供本地榜单。没有限时收卷、隐藏批次、自动全配对、配对矩阵、置信区间报告或长期 Rating。

## 单局

存活者优于已死者；已死者中死亡 Tick 更晚者排名更高；同 Tick 死亡并列；Tick 上限仍存活者并列。初始化淘汰使用死亡 Tick −1。

每个槽位的名次分 = `(排名低于自己的对手数 + 0.5 × 与自己并列的对手数) / (参赛人数 - 1)`。双人仍为胜 1 分、平 0.5 分、负 0 分。独占第一记胜，并列第一记平，其余名次记负；并列第一的名次分可能高于 0.5。

击杀、炸墙和行动次数不额外加分。Bot 故障按规则淘汰后正常参与胜负；宿主 / 写盘 / 引擎失败不产生有效胜负。精确规则见[游戏规则](rules.md)。

## 榜单

只有新版 `run` 记录同时满足以下条件才计入：

- 运行状态为 completed；
- 已完成世界校验；
- 终局结果 valid；
- 2～8 个槽位与得分有效，全部得分之和为参赛人数 / 2。

对每个 Bot 快照汇总局数、胜 / 平 / 负和总分，平均得分为 `累计名次分 / 参战槽位数`。按平均得分降序，同分采用并列名次（如 1、1、3）；内部使用精确分数判断并列。未参赛 Bot 不进入排名。

快照 ID 是统计身份，显示名称不是唯一键。槽位交换时仍按 Bot ID 计分。每次成功的重新运行计为独立单局，失败 / 中断不计分；旧版批次不混入。

同一个 Bot 可以占据多个槽位，各自使用独立运行实例和 Bot Seed。榜单按槽位分别累计参战与得分，有效对局总数仍计一场。

不同 Bot 的参赛人数、对手和局数可能不同；重复相同输入不会增加新的地图证据。这是本机运行统计，不能据此声称统一评测、跨模型全面能力或跨版本长期评级。基准 Bot 是工程参照程序。

内置 Random 随机选择六种动作；Safe 不放炸弹，依据未来 6 Tick 的爆炸预测选择安全动作。Heuristic 沿可通行格计算到软墙或对手的最短路径距离，允许先远离目标再绕墙接近；硬墙和已有炸弹阻断路径。放弹仍须有预期用途并通过逃生检查，不预测对手后续动作。

## 开发与快照

模型开发包提供同一 SDK 和公开材料，生成单文件 `bot.cpp`。主应用直接导入并自动编译检查，不管理模型开发时间或源码收卷。

运行保存 WASM 哈希、规则 / 工具版本、地图 Seed 和 Bot Seed；重新导入源码建立新 Bot，不能覆盖旧快照或沿用旧身份的成绩。规则与资源预算变化须重新验证。
