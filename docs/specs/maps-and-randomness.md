# 地图与随机性

## 地图生成器

地图采用 13 × 11、180° 旋转对称地图，支持 2～8 个 Bot 各自为战。槽位按用户选择顺序分配，依次取出生点 `(1,1)`、`(11,9)`、`(11,1)`、`(1,9)`、`(5,1)`、`(7,9)`、`(11,5)`、`(1,5)` 的前 N 个。双人地图与原生成器完全一致。

生成器版本为 2；复现输入包括地图 Seed 和参赛人数。新增槽位成对旋转对应；奇数人数时也清空未使用的旋转对应出生区，以保持地形对称。不同位置的初始可达区域大小可能不同，多人统计不等于统一公平赛程。

生成步骤必须严格固定：

1. 外边界全部为不可破坏墙。
2. 内部 x、y 都为偶数的格子为不可破坏墙，其余为候选道路。
3. 每个出生点及其旋转对应点曼哈顿距离 ≤ 2 的非硬墙格强制清空；出生点及相邻出口可用。
4. 对剩余非硬墙、非强制清空格按 180° 对称关系划分轨道。每个轨道以行优先索引最小的格子为代表；代表按索引升序处理。
5. 每个轨道只取一个 RNG 输出 r；当 `r < 2362232012` 时，将整个轨道置为可破坏墙，否则置为道路。约 55% 的候选轨道放软墙。
6. 完成合法性检查。失败则重新构造候选地图，继续使用同一 RNG 流，不重新初始化。

对称变换为 `(x,y) → (12-x,10-y)`，单格轨道也只抽取一次随机数。强制清空格和硬墙不消耗随机数。

合法性检查：出生点及相邻出口是道路；每个出生点初始可达道路不少于 5 格；旋转对应点的初始区域大小相同；把软墙视为可通行后，所有非硬墙格和出生点连通；全图保持旋转对称。

最多尝试 256 张候选地图，仍不合法则返回地图生成错误。不得在运行时替换 Seed 或使用不公开的备用地图。重试次数记入地图元数据。该构造通常直接满足检查，检查仍用于防止实现偏差。

## 固定 RNG

MapGenerator 使用 xorshift32，仅用于可复现地图生成，不用于密码学：

```text
输入 seed 为 uint32。
state = seed；若 seed = 0，则 state = 0x6D2B79F5。
next_u32():
    state ^= state << 13
    state ^= state >> 17
    state ^= state << 5
    return state
```

每步使用 32 位无符号整数，左移溢出按模 2^32 截断，右移为逻辑右移。Seed 0 和替代值产生相同地图；不同 Seed 也可能生成相同地图。本地单局如实保存用户输入，不建设种子清单管理。

Bot 使用独立 64 位种子，其来源与地图生成流分离。SDK 可以提供固定的整数 PRNG 帮助函数，也允许 Bot 根据传入种子自行实现可复现随机策略。

## 单局随机输入

地图 Seed 默认为独立随机 uint32，也允许用户指定。每个 Bot 槽位使用独立随机 uint64 Seed，按所选槽位保存为 16 位十六进制字符串，不经过 JavaScript Number。

“重新运行”复用原地图 Seed、Bot Seed、槽位和 WASM 快照，保存为新运行。历史录像直接读取记录，不再次执行 Bot。

开发包提供十张公开地图，可选练习逐局换边；Bot Seed 在练习换边时跟随 Bot。主应用没有自动换边、正式案例清单、隐藏地图、封存与披露业务。

保存 Seed 不是唯一复现条件，Bot 重跑还须固定规则、生成器、SDK、WASM、运行时和 fuel。精确规则见 [游戏规则](rules.md)。
