# 炸弹人游戏规则

本文件定义当前玩法参数与结算顺序。修改这些规则时必须更新版本，并重新验收受影响比赛。

## 坐标、状态与动作

左上角为 `(0, 0)`；x 向右、y 向下。网格只含 `FLOOR`、`HARD_WALL`、`SOFT_WALL`。存活 Bot 和炸弹是独立实体，不覆盖网格类型。

游戏初始 `tick = 0`。最多结算 Tick 0 至 499，共 500 次。Bot ID 等于该局出生槽位，和模型身份分离。

每局 2～8 个 Bot 各自为战，没有队伍。所有其他槽位都是对手，同一 Bot 的重复参赛槽位也独立参与移动、伤害和排名。地图固定为 13 × 11，出生点按参赛人数生成，见[地图与随机性](maps-and-randomness.md)。

| 值 | 动作 | 含义 |
| --- | --- | --- |
| 0 | WAIT | 等待 |
| 1 | UP | y − 1 |
| 2 | RIGHT | x + 1 |
| 3 | DOWN | y + 1 |
| 4 | LEFT | x − 1 |
| 5 | BOMB | 在自己的当前位置放炸弹 |

每 Tick 只允许一个动作，不能同时移动和放炸弹。初始炸弹容量为 1，爆炸范围为 3 格。Bot 死亡后不再被调用，已放置炸弹继续存在。

## 每 Tick 的唯一结算顺序

对于 Tick T，严格依次执行：

1. **观察。** 为所有存活 Bot 创建同一份世界快照，只改变 `self_id`。快照不包含任何 Bot 本 Tick 的输出。
2. **调用与验证。** 收集全部动作；非法返回值和运行故障按 SDK 处理。达到故障淘汰阈值者记为本 Tick 死亡，其位置在移动前释放。未达到阈值的故障动作转为 WAIT。
3. **同时移动。** 使用这一步开始时的墙、炸弹和剩余存活者位置，统一解决移动请求。
4. **放置炸弹。** 执行 BOMB；记录 `explode_at_tick = T + 4`。容量已满或格子已有炸弹时，动作无效果。
5. **爆炸闭包。** 找出所有到期炸弹，连同它们触发的连锁炸弹一起确定爆炸覆盖集合。
6. **死亡。** 覆盖集合内所有存活 Bot 同时死亡，`death_tick = T`。
7. **清理。** 同时移除爆炸炸弹和被击中的可破坏墙，记录事件与最终状态。
8. **计分与结束检查。** 结算击杀奖励，仍存活者各加 1 分。 存活者数量 ≤ 1 时结束；否则到达 500 次结算后结束；其余情况推进至 T + 1。

不留跨 Tick 火焰。下一 Tick 可以进入本 Tick 爆炸过的道路。爆炸前发生移动，所以 Bot 可以在到期 Tick 移出危险格；进入危险格则会死亡。

## 同时移动

墙和炸弹所在格不可进入。Bot 可以从自己脚下的炸弹离开，但之后不能重新进入；无需额外“穿过自己的炸弹”权限。

先把移动请求转换为目的地：

- 越界、撞墙或进入炸弹格：原地停留，无动作故障。
- 多个 Bot 请求同一目的地：这些请求全部失败，即使目的地开始时为空。
- 一个 Bot 进入另一 Bot 起始位置：仅当后者成功离开时才允许。
- 双向交换位置和任何移动环全部失败。
- 一条移动依赖链最终到达空格，则整条链成功；最终到达不移动者、失败请求或移动环，则整条链失败。

依赖链只能根据移动请求统一计算，不能根据 Bot ID 逐个移动。失败者原地停留，不另寻替代方向。故障淘汰者在步骤 2 已经不占格子。

示例：A 向 B 原位置移动、B 向空格移动，两者成功；A 和 B 互换位置，两者失败；A 和 B 都向同一空格移动，两者失败。

## 炸弹与连锁爆炸

Tick T 放置的炸弹在 T、T+1、T+2、T+3 都不会自行爆炸，在 T+4 的步骤 5 爆炸。快照中的剩余延迟为 `explode_at_tick - current_tick`；到期炸弹为 0。连锁可以使炸弹提前爆炸，包括本 Tick 刚放置的炸弹。

爆炸包括炸弹自身格，沿上、右、下、左各传播最多 3 格：

- 地图外：停止。
- 不可破坏墙：停止，该墙格不进入覆盖集合。
- 可破坏墙：该格进入覆盖集合并标记销毁，停止该方向传播。
- 炸弹：该格进入覆盖集合，触发该炸弹，停止当前炸弹在该方向的传播；被触发炸弹再独立传播。
- Bot：该格进入覆盖集合，传播继续，Bot 不阻挡火焰。
- 道路：该格进入覆盖集合，传播继续。

整个爆炸阶段使用同一份“放置后、爆炸前”的墙和炸弹快照。所有被击中的可破坏墙在阶段结束后才移除，因此一枚炸弹炸掉墙不会让另一枚炸弹在同 Tick 穿过它。

从所有到期炸弹开始求连锁闭包，每个炸弹最多处理一次。结果不能依赖队列或炸弹 ID 顺序。各炸弹仍保留自己的 owner，即使是对手触发的连锁。

## 积分、排名与击杀归因

局内积分从 0 开始：每个 Tick 的故障、移动、爆炸和清理结束后，仍存活者获得 1 分；等待或无效果的合法动作也能获得生存分。死亡的当 Tick 不得生存分。每击杀一名敌人获得 100 分，奖励相当于存活 100 回合。

爆炸死亡按覆盖死亡格的不同炸弹 owner 归因：每个不同于死亡者的 owner 各记一次击杀并得 100 分；同一 owner 的多枚炸弹不重复计分。自杀不给击杀分；混合命中中排除死亡者自身，其余 owner 正常得分。连锁按实际爆炸炸弹的 owner 计分，不把整条连锁归给起爆者。死亡者已放的炸弹仍能击杀得分；运行故障淘汰不奖励任何人。炸墙不加分。

最终仅按总积分降序排名，同分并列，不用存活状态、死亡 Tick 或击杀数破同分。即使已经死亡，也可能凭之前或延迟的击杀积分排在存活者前面。死亡 Tick 仍用于回放诊断。初始化淘汰记 `death_tick = -1`；初始化后存活者不超过一人时，直接结束，所有人均为 0 分并列。正常结算后存活者不超过一人或达到 500 回合上限时结束，不补发剩余回合积分。

当前炸弹人规则版本为 2。旧版按存活顺序排名的录像仍按规则 1 验证和播放，旧记录与旧规则重赛不进入规则 2 的榜单。重赛保留原比赛规则、地图、Bot 快照与种子。事件保留完整爆炸 owner 集合和每笔击杀奖励；状态与终局保存总积分、击杀数和生存 / 击杀积分拆分。

## 需要覆盖的规则例子

等待与无效移动；争抢空格；交换位置；链式跟随；移动环；新放炸弹延迟；到期 Tick 逃生；新炸弹被连锁；死亡者炸弹继续爆炸；多炸弹同时撞软墙；墙后目标受到保护；多人同 Tick 死亡；全部同时死亡；上限存活并列；故障淘汰释放位置。
